# Brainstorm Template

## Brief

目标：
把模糊想法通过结构化对话变成用户认可的设计，再把设计交给 PRD、plan、brief 或执行流程。

模式：
brainstorm；按 `shared/brainstorm.md` 完成共识对话和设计门禁，设计被批准后提供后续产物选项，不静默继续。

上下文：
按 `shared/context-discovery.md` 做最小必要发现，先看项目现状（文件、文档、近期改动）以判断规模档位；探索保持只读。

要求：
一次只问一个聚焦问题，先弄清目的、受众、约束和成功标准。写回理解时分清用户说的内容和自己的假设，并邀请纠正。按规模分档工作：探针（可行性问题，产出是建议且代码一次性）、有界（仓库已有流程的小改动，对话内简短设计后等待明确同意）、架构级（新项目/新子系统/接口关系变化，先给 2-3 个方案及权衡并给出推荐，再分节呈现设计逐节确认）。任何实现动作前必须满足所选档位的设计门禁；批准只覆盖当前阶段，下一阶段需再次批准；发现隐藏复杂度时停下升级档位，不降级。架构级设计呈现前先自审：无占位符、内部一致、范围单一、无歧义。设计被批准后转入 prd-only、plan-only、brief 或有界设计的直接执行；高风险信号仍按 `shared/safety.md` 走 analysis-first。
